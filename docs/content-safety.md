# AIコンテンツフィルター

管理画面 → アンチチート → 検知設定 → **AIコンテンツフィルター** で有効にして保存します。
初期状態では無効です。アンチチート全体も有効にしてください。除外チャンネル・除外ロールは従来どおり適用します。
`config.json` の `pexAi.endpoint` / `pexAi.apiKey` を使用し、モデルは `gemma4:e2b-it-qat` 固定です。
APIキーをブラウザーへ公開しません。モデル一覧ではこのモデルはPlus/Pro対象です。
有効化したサーバーの検査対象本文・画像フレームは設定済みPEX APIへ送信されます。

## 判定と表示

- 「検知した投稿の扱い」でネタバレ代理投稿（初期値）か投稿を削除を選び、設定を保存します。
- 削除モードは全体の自動削除スイッチとは独立して該当投稿だけを削除します。代理投稿はせず、検知ログに記録します。スコア加算・タイムアウトは初期OFFです。
- 判定後に本文/添付/編集時刻が変わった場合は、古い判定で削除しません。
- 以下のEmbed・添付の保全処理はネタバレ代理投稿モードの説明です。

- 軽い性的表現（H系）、露骨な性的表現（R18）、暴言、差別、脅迫、残虐表現を個別に有効化。
- 画像と文章それぞれの確信度しきい値を設定。低いほど厳格。AIの自己申告スコアであり、校正された確率ではありません。
- 軽いH系には独立したしきい値を用意（画像0.2、文章0.7）。R18など他カテゴリのしきい値は下げません。軽い演出も対象にする初期設定のため、誤検知が多ければH系画像のしきい値を上げてください。
- 添付画像、直接画像URL、リンク先HTMLの `og:image` / `twitter:image`、Discordの画像プレビューを取得。
- GIF・アニメーションWebPは最初から最後まで等間隔に最大12フレームを抽出（初期値6）。全フレーム検査ではなく、短い挿入フレームを見逃す可能性があります。
- GIF・アニメーション画像のフレームは元解像度・透過を維持した無劣化PNGとして複数枚送ります。縮小・JPEG再圧縮はしません。静止画は従来のJPEG処理です。同じ画像データは重複送信しません。合成関数は比較試験用に残しています。
- URLのHTMLページはプレビュー画像のみを対象とし、ログイン必須ページ、JavaScript描画、動画/MP4として配信されるGIF風動画の全編解析には対応しません。IPv6のみのホストも対象外です。
- 警告Embedに表示名・ユーザー名・ユーザーID・元投稿ID・日時・カテゴリを表示。本文をネタバレ表示、画像/GIFは `SPOILER_` 添付にします。Embedの画像欄には設定しません。
- 元の添付は全件再取得し、代理投稿成功後に元投稿を削除します。削除失敗時は代理投稿を取り消します。投稿者本人への成り済ましWebhookは使いません。
- 長文はネタバレ付きテキストファイルに保存。メンション通知は無効。返信スレッド関係・リアクション・元メッセージURLは引き継ぎません。
- この検知は初期設定ではスコア加算・タイムアウト・過去投稿の一括削除を行いません。AIスコア加算をONにすると既存の自動タイムアウトにも反映されます。同時に別の検知が発生した場合、その検知のスコア・処罰ルールは引き続き適用されます。
- 編集・遅延リンクプレビューも再検査し、同じ置換済み投稿への重複代理投稿を抑制します。

## 運用上の制限

削除には「メッセージ管理」、代理投稿にはさらに「メッセージ送信（スレッド内も）」「埋め込みリンク」「ファイル添付」が必要です。
Discordではユーザーの送信前には検査できず、解析完了まで元投稿が表示されます。ネタバレ表示は年齢認証ではなく、閲覧者が解除できます。
モデルの誤検知・見逃しがあります。実APIの応答は数十秒かかることがあります。

API障害・不正JSON・容量超過・権限不足時は元投稿を保持し、未検査はサーバー側の運用ログだけに記録します。Discordの検知通知と違反ログは検知時のみです。代理投稿失敗は検知ログに記録します。
初期設定は画像1件8MB、1投稿4画像、AI応答90秒、同時処理2投稿、待機32投稿（待機60秒まで）。
代理投稿は1添付10MB、合計24MB、最大10添付。完全に保全できない投稿は削除しません。
外部URL取得は公開IPv4に限定し、DNS解決先を固定、リダイレクトも再検査し、サイズ・時間を制限しています。
解析キャッシュは全体で最大2000件、初期保持時間60分です。サーバーごとに分離し、本文特徴・小さな画像特徴・判定結果をメモリ上に保持します。再起動時には消去されます。

## キャッシュ・入力削減

「このサーバーの判定キャッシュを削除」は設定保存とは独立して即時実行します。
設定アクセス権を検証する専用APIで、そのサーバーのキャッシュだけを消去します。
消去前に開始された推論結果でキャッシュが復活することも防ぎます。

完全一致は安全判定も再利用。同じ入力の同時リクエストもまとめます。
類似キャッシュは初期値90%以上。文章は文字3-gram、画像は縮小した色・輪郭の近さで比較します。
意味の一致率やAIの確信度ではありません。30文字未満の異なる文章や、否定・相談・引用マーカーの変化は対象外ですが、あらゆる意味変化は判別できません。
類似再利用はネタバレモードの検知済み結果のみ。安全だった類似画像で危険画像を素通ししたり、似ているだけの投稿を削除したりしないためです。
削除モード、またはAIスコア加算ONの場合は完全一致だけを再利用します。類似再利用の有効/無効・しきい値・保持時間は管理画面で変更できます。
ログの `analyses.cache` は `exact` / `similar` / `miss`、`similarity` は再利用の類似度です。現在のしきい値・カテゴリ設定で毎回再評価します。

固定の分類プロンプトを先頭に置き、ユーザーID・時刻・履歴はAIへ送りません。加算ON時のみ、加算上限と有効カテゴリを追加します。
URLのみの本文は画像取得を有効にしている場合に別の文章検査を省略し、対象が見つかれば残りの画像のAI解析を打ち切ります。ログのカテゴリは全件網羅ではありません。
同一フレームの重複送信も省略します。本文の切り捨てによる検査漏れは避けています。
回答は `submit_verdict` 関数のツール呼び出しを1件だけ要求します。引数は6カテゴリの数値と短い日本語説明（explanation）をJSONスキーマで指定し、本文へのJSON回答は要求しません。出力上限は推論の余裕を含め2048トークンです。関数名違い・複数呼び出し・通常本文・途中切れは未完了とし、安全判定として保存しません。関数は判定値を返すだけで、モデルが任意の処罰ツールを実行する構成ではありません。欠けたカテゴリをゼロで補完することはありません。
`reasoning_effort: low` と `chat_template_kwargs.enable_thinking: true` で低い推論量を要求します。実際の推論動作はProxy・モデルに依存します。対応仕様は [Ollama OpenAI互換API](https://docs.ollama.com/api/openai-compatibility) を参照してください。

RAGは関連資料を検索して追加する仕組みで、KVキャッシュ自体ではありません。短い分類規則には動的な検索文書を追加せず、共通prefixと結果再利用で送信量を減らしています。
KVキャッシュの実ヒットはProxy・推論エンジンの設定とルーティングにも依存し、Botから保証できません。
`keep_alive` はモデルの常駐時間であり、KVヒット率ではありません。
今回の試験応答1件では `prompt_tokens=461`、`cached_tokens=456` を確認しました。最終構成の恒常的なヒット率や画像エンコードの再利用を保証する数値ではありません。
参考: [llama.cppのprompt cache仕様](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)、[Ollama FAQ](https://docs.ollama.com/faq)。

### 今回の変更：個別フレーム・通知・任意加算

AIスコア加算は `awardScore=0` が初期値。ON時は `maxAiScore`（初期10、設定範囲1～100）を上限として、AIが `suggestedPoints` に0〜上限の整数、`pointsReason` にその点数が妥当な理由を返します。分類強度と上限の掛け算は行いません。上限超過・非整数・理由欠落は不正応答として扱います。有効カテゴリが検知閾値を超えた解析のみ加算対象とし、複数解析では提案点の最大値を1投稿につき1回適用します。検知してもAIの提案が0点なら加算しません。加算OFF・未検知は0点です。上限・有効カテゴリ・加算ON/OFFが変われば同じ画像でも再判定します。

画像類似キャッシュは全抽出フレームの特徴と枚数を比較します。先頭だけ一致して後半が異なる動画を同一扱いしないようにしています。

厳格JSON＋6フレーム個別送信で `caption.gif` を再試験した結果は全カテゴリ0（約19.5秒）でした。画像の送信方法だけで見逃しは解消していません。上の合成方式の結果は以前の比較試験です。

前回は本文JSON指示とツール指定を混在させた試験で通常本文が返りました。今回は本文JSON指示を外し、指定した関数の `tool_calls` が返ることを確認できました。前回の結果からProxyのツール非対応を結論づけることはできません。

現在の個別6フレーム＋厳格JSON方式でWebPを再検証し、`suggestive=0.7`（他0）、約19.2秒で検知しました。加算ON・上限10点なら7点です。更新後の回帰テスト30件は成功しています。

### 画像＋本文の同時判定と追加JPG

本文単体で未検知の場合も、画像判定には同じ投稿の本文を添えて渡し、組み合わせの文脈を判定します。本文単体で検知済みなら従来どおり残りの画像解析は省略します。文章検査OFF時は本文を送信せず、画像だけを判定します。URLのみの本文も重複送信しません。画像と本文を組み合わせた判定には画像用しきい値を使います。

画像キャッシュの類似比較は、本文のSHA-256も一致する場合だけ再利用します。画像が同じでも本文が変われば再判定します。

`676rvfv.jpg` を1フレーム（530×768のJPEG）として実APIで検査。画像単体でsuggestive=0.8、他0（約17.2秒）。試験用の中立文「この画像についてどう思いますか？」を同じリクエストに添えてもsuggestive=0.8、他0（約16.7秒）で、いずれもH系の警告対象でした。これらの成功は全画像・全文章に対する精度保証ではありません。回帰テスト32件成功。

再現例: `npx tsx scripts/test-content-safety.ts --file <画像パス> --caption <本文>`。

通常運用の抽出枚数設定（初期6、上限12）は維持しています。全23フレームの送信は今回の比較試験です。

### クエリ付きDiscord GIFリンクと抽出枚数の比較

本文内の直接URL、`<URL>`、`[表示名](URL)`、ネタバレで囲まれたURLを抽出し、署名クエリ（ex/is/hm等）を削除・並べ替えずに取得します。Markdownの終端括弧は除外し、Markdownでエスケープされたアンパサンドを戻します。添付なしのリンク投稿でも取得したGIFを検査し、検知した画像は元GIFのネタバレ添付として保全します。取得できないリンク（期限切れ等）は未完了扱いで元投稿を残します。

指定されたm166hr4.gifのDiscord CDNリンクを実際に取得（4,868,882バイト）してテストしました。元解像度PNGの3枚では全カテゴリ0、6枚ではsuggestive=0.7（他0）でした。caption.gifとアニメーションWebPは3枚でもsuggestive=0.7でしたが、全サンプルで同じ結果になるわけではありません。

このため標準抽出枚数は6枚を維持しています。序盤～終盤を等間隔に抽出するため、全23枚を送る設定ではありません。管理画面で3枚へ変更すると先頭・中央・末尾になりますが、今回のリンクGIFでは見逃しが発生しました。保存済みの枚数指定も尊重します。

### AIの短い判定理由

同じ `submit_verdict` 呼び出しに `explanation` を追加しました。日本語の一文・最大80文字で、目視できる特徴などの短い説明を要求します。推論手順・元投稿の引用・人名・URL・露骨な描写は要求しません。説明だけを取得する追加API呼び出しはありません。

ネタバレ代理投稿とDiscordの検知通知は「AIの判定理由（参考）」欄に、保存ログと管理画面のログは `AI理由：…` として表示します。削除モードでも理由を記録します。完全一致キャッシュは理由ごと再利用し、類似キャッシュの場合は「類似投稿の判定理由」と表示します。説明が欠けた有効な旧形式の判定は検知を捨てず、説明未取得と表示します。

413分割時は最大スコアを返したバッチの説明を採用します。AIの説明は参考情報で、しきい値・カテゴリ・スコア加算の数値判定を変更するものではありません。改行の整理、80文字への制限、Discord表示時のMarkdown/メンション対策を行います。

実APIでcaption.gifはsuggestive=0.7と短い日本語説明、676rvfv.jpgはsuggestive=0.8と「性的なポーズをとった女性のイラストである。」を確認しました。関連回帰テスト45件とルートの `tsc --noEmit` が成功しました（今回の環境では以前の依存不足エラーは出ていません）。実Discordへのテスト投稿は行っていません。
