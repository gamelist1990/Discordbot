# ACのリアルタイム処理

メッセージ作成・編集を受信すると、本文と添付一覧を固定し、メッセージIDと版で重複イベントを除外する。本文、メンション、同文連投、チャンネル横断投稿など、通信を使わないルールはユーザー単位で受信順に評価する。このキューには削除、処罰、通知、ファイル保存を含めない。

違反時は設定に従って削除を要求する。事前のメッセージ取得は行わない。削除APIが応答待ちでも、同じユーザーの次の投稿を評価して削除要求を送れる。削除済みエラー（10008）には加点・通知せず、権限不足などの失敗は検知ログの `deleteError` に残す。

URL追跡、GIF、画像重複、AIは、それぞれ別の検査キューを使う。古いメッセージの検査結果は、編集・削除された後に適用しない。AIの通信失敗時の再試行は従来どおり継続する。通常ルールで検知した投稿には追加のAI検査を始めない。

## メンションの集計

Discordの一意なメンション対象一覧ではなく、本文の `<@ID>`、`<@!ID>`、`<@&ID>` の出現回数を数える。同じロールを6行に書いた場合も6回として扱う。返信先のメタデータだけでは加算しない。[Discordメンション仕様](https://github.com/discord/discord-api-docs/blob/main/developers/reference.mdx)

メンション履歴はサーバーと投稿者単位で共有し、チャンネルをまたぐ投稿を合算する。編集では同じメッセージの古い集計を差し引き、新しい本文を登録する。削除されても直前の攻撃回数は監視時間が満了するまで残し、投稿してすぐ消す回避を防ぐ。

初期値は30秒内に同じユーザー5回、ロール合計5回、全メンション合計10回のいずれかで検知。1投稿内だけでもしきい値に達すれば即時検知する。管理画面で設定した有効・無効、除外、自動削除、自動タイムアウト、スコア処罰を適用する。メンション監視時間は1〜3600秒、各検知回数は1〜4096回。

タイムアウト実行中と過去投稿削除の実行中は、同じ投稿者の要求をまとめる。設定保存も最新の状態にまとめ、連打のたびに重複したディスク書き込みや全チャンネル走査を増やさない。

ログの `decisionLatencyMs` は受信から対処判断まで、`detectionLatencyMs` は削除等の応答待ちも含む時間。`processingLane` で即時判定と外部検査を区別する。Discordのネットワーク・レート制限によるAPI完了時間は、このローカル判定時間とは別に発生する。

## 検証

```sh
node --import tsx --test --test-concurrency=2 tests/anticheat-realtime.test.ts tests/anticheat-mention-load.test.ts tests/anticheat-detection.test.ts tests/anticheat-load.test.ts tests/cross-channel-spam.test.ts tests/exclusion-policy.test.ts
./node_modules/.bin/tsc --noEmit
```

負荷テストはDiscord APIを模擬し、1000人・1万投稿の検知数と削除要求数を確認する。実サーバーでのAPI応答時間を保証する測定ではない。変更を反映するにはBotプロセスの再起動が必要。
