# AntiCheatの除外設定

「除外対象」の「+ IDを追加」で入力欄を開き、候補またはDiscord IDを指定して「追加」します。入力中の空欄は保存済みIDと分離して保持します。以前は空欄を即座に空配列へ戻していたため、追加ボタンから入力欄を開けませんでした。

ロールはロール名とID、チャンネルは名前・種類（テキスト、ボイス、カテゴリ、スレッド等）とIDを表示します。候補は対象サーバーから取得します。種類違い・別サーバーのID・重複追加は拒否します。一覧にないIDはサーバーへ問い合わせます。Botがアクセスできない対象は追加できません。既存設定の削除済みIDは、消去できるよう「対象を確認できません」と表示して保持します。

## チャンネル別の詳細

- 「すべての検知を除外」: そのチャンネルでのメッセージ検知をすべてスキップします。
- 「選択した検知だけ除外」: チェックした検知だけをスキップします。例えばAIコンテンツフィルターだけを除外しても、チャンネル横断スパムやワードフィルターは全体設定に従って動作します。
- 未選択の個別設定には除外効果がありません。
- カテゴリの設定は子チャンネルへ、親チャンネルの設定はスレッドへ引き継ぎます。除外は合算され、子設定から親の除外を打ち消すことはできません。
- 除外ロールを持つユーザーはメッセージ検知と参加時のアンチレイド集計から除外します。ロールの全除外がチャンネルの個別設定より優先されます。
- 参加人数を監視するアンチレイドはチャンネル別設定の対象外です。
- 検知の除外と、別機能のチャット・アバター変更ログは別設定です。

変更はページの保存操作で反映されます。保存エラーでは編集内容を残し、APIからの理由を表示します。保存前に開始済みの処理には、その時点の設定が適用されます。

既存の `excludedRoles` / `excludedChannels` は全除外として維持し、個別除外を `channelDetectorExclusions: { "チャンネルID": ["contentSafety"] }` に保存します。従来設定を読み込んだ際の個別除外の既定値は空です。全体で無効の検知を、チャンネル設定から有効にはしません。

## 確認内容

`tests/exclusion-policy.test.ts` で個別除外・ロールと親階層の優先関係・横断スパムの先行処理・設定保存と解除・APIの対象サーバー制限と種類検証を確認しています。

`node scripts/check-exclusion-ui.mjs` は実コンポーネントを使ったPC/スマホ幅の操作テストです。DiscordのメタデータAPIはモックで、実サーバーの設定変更は行いません。入力欄保持・誤種類・ID追加・名前表示・個別選択・保存状態の再表示・削除・横はみ出しを確認しています。

関連回帰テスト42件とWebビルドは成功。全体の型チェックには既存の依存不足（gif-encoder-2、opentype.js）、フロントエンドには既存の未使用importとArray.atのlib設定エラーが残っています。
